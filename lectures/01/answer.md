## 宿題

- 取り組んだレベル：実装
- やったこと：
  - `app/ask.py` に会話モード（`--chat`）を追加し、会話履歴を保ったまま続けて質問できるようにした
    - 例：`uv run python -m app.ask --chat "LoRAとは何ですか？"`
    - 履歴は SDK の `client.chats.create()` で作った `Chat` が保持し、`send_message()` のたびにそれまでの履歴をまとめて送る
    - 引数なし・質問1つだけの実行は従来どおり（履歴なしで1回だけ質問する）
  - 会話中に使えるコマンドを追加した
    - `/help`：コマンドの一覧を表示
    - `/history`：履歴を1ターン1行の一覧で表示（質問・回答とも30文字で省略、ID付き）
    - `/history ID`：指定したターンの質問と回答を全文表示
    - `/reset`：履歴を消去
    - `/exit`（`/quit`、Ctrl+D）：終了
  - ターンごとと累計の入力・出力トークン数、応答時間を表示するようにした。終了時には累計を表示する
  - API エラー（429 など）が起きても会話は終わらない。失敗した質問は履歴に残らないので、待ってから同じ質問をやり直せる
- 結果：
  - API 呼び出しを偽物に差し替えて、会話の継続、`/help`・`/history`・`/history ID`・`/reset`・`/exit`、不正な ID や不明なコマンドの扱い、エラー後も会話が続くことを確認した
  - 既存のテスト（`uv run pytest -q`）は 11 件すべて通過した
- 気づき・疑問：
  - LLM 自体は前の会話を覚えていない。「会話の記憶」は、毎回それまでの履歴をすべて送り直すことで実現している
  - そのため、ターンが進むほど入力トークン数が増えていく。長い会話ではコストやレート制限（トークン数の上限）に早く達しそうです。
  - 最初は履歴を `{"role": "user", "parts": ["質問"]}` の形の辞書で作ったが、SDK の `types.Content` では `parts` の要素は文字列ではなく `Part` でないといけないため、型チェックで弾かれた。SDK の `Chat` を使うと、履歴の形式を自分で管理しなくてよい
