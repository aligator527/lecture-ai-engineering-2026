## 宿題

- 取り組んだレベル：実装
- やったこと：
  - `app/tools.py` に `save_learning_log(title: str, content: str) -> str` を追加。`learning_log/` に `YYYYMMDD-HHMMSS-題名.md` で保存する。題名からファイル名に使えない文字や `/`・`..` を取り除き、フォルダの外に書き込まないようにした（`../../etc/x` → `…-etc_x.md`）。空の title / content は保存しない。
  - `app/agent.py` で `agent.tool_plain(tools.save_learning_log, requires_approval=True)` と登録し、`output_type=[str, DeferredToolRequests]` に変更。
  - CLI に `run_with_approval()` / `ask_approvals()` を追加。結果が `DeferredToolRequests` の間、`result.output.approvals` の呼び出しごとにツール名と引数を表示して `[y/N]` で確認し、`True` または `ToolDenied("利用者が保存を拒否しました。")` を `DeferredToolResults` に入れて、`message_history=result.all_messages()` と一緒に再度 `run_sync` する。`usage=result.usage` も渡し、`[usage]` が2回の実行の合計になるようにした。
  - `INSTRUCTIONS` に「学習の記録を頼まれたら、文章で確認を取らずに save_learning_log を呼ぶ（保存前の承認はシステムが利用者に確認する）」を追加（最初の書き方からの変更理由は「気づき」に記載）。
- 結果：
  - 承認（y）：「LoRAとQLoRAの違いを調べて、学習ログに保存して」→ `search_glossary` ×2 → `save_learning_log` が承認待ちで止まり、引数（title / content）が表示された。`y` で `learning_log/20261109-051836-LoRAとQLoRAの違い.md` が作られ、モデルは「学習ログに保存しました」と回答。
  - 拒否（n）：「今日学んだ『RAG』の意味を学習ログに保存して」→ `n` を押すとファイルは作られず、ツールの戻り値が「利用者が保存を拒否しました。」になり、モデルは内容を示して「よろしければ『保存して』とお知らせください」と聞き返した（`requests=3`）。
  - `uv run pytest -q` は 15 passed（TestModel が `save_learning_log` も呼ぶが、承認待ちとして数えられて通る）。`learning_log/` は `.gitignore` 済みなのでコミットされない。
- プラスα（実装問題を発展させた取り組み）：
  1. **承認時の編集（y / N / e）**：`e` を選ぶと、モデルが作った引数（title / content）を1つずつ書き直してから許可できる。`ToolApproved(override_args=...)` で、モデルの引数を利用者の引数に差し替えて実行する。本文は複数行で入力でき（「.」だけの行で終了）、Enter や「.」だけなら元の値のまま。
     - 実行結果：モデルの題名「LoRAの基礎知識」を「LoRAメモ（編集済み）」に直して承認 → `learning_log/20261109-052345-LoRAメモ（編集済み）.md` として保存された。
  2. **対話モード `--chat`**：`message_history` を引き継ぎ、`exit` まで会話を続けられる。拒否したあとに「やっぱり保存して」と頼み直せる。`--trace` はそのターンの分だけ表示する（`print_trace(result, start)`）。API エラーが起きても対話は終了せず、もう一度質問できる。
  3. **保存済みログを読むツール**：`list_learning_logs()`（ファイル名と題名の一覧を新しい順に返す）と `read_learning_log(filename)`（本文を返す）。読むだけで取り消す必要がないので、**承認なし**で登録した。「承認が必要なのは取り消しにくい操作だけ」という区別をつけた。ファイル名は `Path(filename).name` にしてから読むので、`../secret.md` のようにフォルダの外は読めない。
     - 実行結果：「これまでの学習ログを見せて、中身も読んで」→ `list_learning_logs({})` → `read_learning_log({'filename': '…LoRAメモ（編集済み）.md'})` の順に呼ばれ、中身まで答えた（`requests=3`）。
  4. **`--yes` / `--no`**：承認を自動で許可・拒否する（同時には指定できない）。対話できない環境（CI やスクリプト）で使う。`--no` で実行するとファイルは作られなかった。
  5. **自動テスト `tests/test_learning_log.py`（14件、API キー不要）**：保存先は pytest の一時フォルダに差し替える。
     - `make_quiz`：問題と答えが第2回の用語と対応すること、用語が無い回のメッセージ
     - 学習ログ：保存→一覧→読み込み、フォルダの外に書けない・読めないこと、空入力、同じ秒・同じ題名で上書きしないこと
     - 承認の流れ（TestModel が `save_learning_log` を呼ぶ）：y で保存される、n で何も保存されない、e で直した題名で保存される、`--yes` / `--no` では利用者に聞かない、承認の前後の `requests` が合算される
     - 全体：`uv run pytest -q` → 29 passed
  6. **細かい改善**：同じ秒に同じ題名で保存しても上書きしないよう、ファイル名に `-2` などの連番を付けた。
- 気づき・疑問：
  - 承認時に**モデルが作った引数がそのまま見える**ので、「何を保存しようとしているか」を人が確認できるのが Human-in-the-Loop の価値だと感じた。一方で、本文が長いと確認がつらいので、要約表示や編集してから承認する仕組みもほしい。
  - 承認で止まると `run_sync` が一度終わるため、`usage` を引き継がないと LLM 呼び出し回数が過小に表示される（最初は `requests=1` と出ていた）。
  - 「RAG」は用語集の検索で別の用語（一致率）が当たってしまい、モデルは「用語集にはない」と言いつつ一般知識で本文を書いた。保存する内容が用語集に基づくかどうかを、承認時に人が見分ける必要がある。用語集に RAG を足すか、検索の部分一致の精度を上げたい。
  - 拒否されたあとモデルが「保存して」と再依頼を促したが、1回だけ質問する CLI では続けられなかった → プラスαの `--chat` で、拒否のあとに頼み直せるようにした。
  - **二重確認の問題**：最初の `INSTRUCTIONS`（「保存前に利用者の承認が入る」）では、モデルがツールを呼ばずに「保存してよろしいですか？」と**文章で確認**してくることがあった。システムの承認と合わせて確認が2回になる。「文章で確認を取らずに save_learning_log を呼ぶ（承認はシステムが行う）」と書き換えたところ、`--yes` で2回試して2回ともすぐにツールを呼ぶようになった。承認を人に任せる仕組みがあることも、モデルに伝える必要がある。
  - 編集して承認した場合、`--trace` の `[tool call]` はモデルが作った元の引数（「LoRAの基礎知識」）のままで、`[tool return]` だけが編集後のファイル名になる。履歴には「モデルが何をしようとしたか」が残るので、監査には都合がよいが、読むときは注意が必要。
